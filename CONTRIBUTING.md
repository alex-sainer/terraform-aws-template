# Contributing

Thanks for taking the time. Issues and pull requests are welcome, from first-time users as much as from people who run Terraform every day.

## Before you start

- For a bug, open an issue with the bug template. Include the tool and version, your `pipeline.json`, the command, and the output.
- For a larger change, open an issue first and describe the problem you want to solve. That avoids work on something that does not fit the template.
- For a typo or a small fix, open the pull request directly.

## Set up

Install the tools from [docs/tooling.md](docs/tooling.md), then:

```bash
pre-commit install
pre-commit run --all-files
```

The hooks format and validate the Terraform code, lint the shell scripts and the workflows, scan for secrets, and run the pipeline mapping tests. CI runs the same hooks, so a green local run is a green pull request.

## Make the change

- Terraform code: `tofu fmt` (or `terraform fmt`) is enforced. New variables need a `description`. Secret variables need `sensitive = true`.
- Shell scripts: must run under bash 3.2 (macOS default). No associative arrays, no `mapfile`, no `${var,,}`. shellcheck and shfmt are enforced; the format rules are in `.editorconfig`.
- `scripts/pipeline.sh`: every change to the branch mapping needs a test in `scripts/pipeline-test.sh`. Run it with `bash scripts/pipeline-test.sh`.
- Workflows and `.github/actions/tf-run/`: run `bash scripts/lint-workflows.sh`. It lints the templates and every variant that `scripts/setup --render` produces.
- `.github/workflows/terraform-preview.yml.template` is generated by `scripts/setup`. Change the generator in `scripts/setup`, not the file.
- `pipeline.json` schema: if a key changes, update `scripts/pipeline.sh`, `scripts/setup`, the tests, README, and `docs/pipeline.md` together.
- Documentation: if behavior changes, change the README or `docs/pipeline.md` in the same pull request.

## Open the pull request

Fill in the pull request template. Keep pull requests focused on one change. Say when the change is breaking for repositories that were created from this template, because they have to adopt it by hand.

Pull requests from forks run CI, but not `/tf plan`: the Terraform workflows are off in this repository and would exclude forks anyway. If a change needs a real plan against AWS, a maintainer pushes the branch to this repository.

## Keep dependencies current

Dependabot updates the pinned GitHub Actions and the AWS provider. The pre-commit hook versions are not covered; update them with:

```bash
pre-commit autoupdate
pre-commit run --all-files
```

After a provider update, regenerate both lock files for Linux and macOS and commit them:

```bash
rm .terraform.lock.hcl bootstrap/.terraform.lock.hcl
tofu providers lock -platform=linux_amd64 -platform=darwin_arm64
tofu -chdir=bootstrap providers lock -platform=linux_amd64 -platform=darwin_arm64
```
