# Notes for coding agents

This is a GitHub template repository for AWS projects with Terraform or OpenTofu. The Git branch selects the environment; one Terraform workspace per environment; one shared S3 state bucket. Read [README.md](README.md) for the model and [docs/pipeline.md](docs/pipeline.md) for the GitHub Actions pipeline before changing anything. This file only lists what is easy to get wrong.

## Layout

- `_*.tf`, `example-s3-bucket.tf` — the Terraform root. New resources are new `.tf` files beside the example.
- `bootstrap/` — separate root with local state that creates the state bucket once.
- `environments/<env>.tfvars`, `<env>.backend.tfvars` — per-environment values and backend. `<env>.secrets.tfvars` and `<env>.tfplan` are gitignored.
- `pipeline.json` — tool, stages, branch mapping, preview mode. The single source of truth for local runs and CI.
- `scripts/tf` — the only way plan, apply, init, import are run, locally and in CI.
- `scripts/pipeline.sh` — reads `pipeline.json`. Every other script asks it; nothing else parses the file.
- `scripts/setup` — interactive CLI that writes `pipeline.json`, env files, and the workflows.
- `scripts/pipeline-test.sh` — tests for `pipeline.sh` with their own fixtures.
- `scripts/lint-workflows.sh` — actionlint and zizmor over the templates and every rendered variant.
- `.github/actions/tf-run/` — composite action and scripts for OIDC, the workspace lock, and `scripts/tf`.
- `.github/workflows/*.yml.template` — the Terraform workflows, inactive in this repository.
- `.github/workflows/ci.yml` — the only active workflow here. Runs the pre-commit hooks, no AWS.

## Invariants

- Never rename a `.yml.template` to `.yml` in this repository. Derived repositories do that through `scripts/setup`. `ci.yml` stays the only active workflow.
- `terraform-preview.yml.template` is generated by `scripts/setup` (`render_preview_workflow`). Edit the generator, then run `scripts/setup --render`.
- The branch-to-workspace mapping lives only in `pipeline.json` and is read only through `scripts/pipeline.sh`. Do not hardcode branch or workspace names in scripts, workflows, or Terraform.
- Workspace `default` is forbidden. Environment names and preview slugs match `^[a-z0-9][a-z0-9-]*$`; stage names must not be `preview` or start with `preview-`.
- In CI, `.github/actions/tf-run/*.sh` run from the default branch (copied before checkout); `scripts/tf` and `scripts/pipeline.sh` run from the pull request commit. Keep security checks in `gate.sh` and `lock.sh`, never in `scripts/`.
- `scripts/tf apply` only applies the plan file written by `scripts/tf plan`. Do not add a way to apply without a plan file.
- The lock in the state bucket is held by a pull request from `/tf plan` until the pull request closes or `/tf unlock` runs, also after a successful `/tf apply`. Do not release it after apply.
- All shell must run under bash 3.2 (macOS). No associative arrays, no `mapfile`, no `${var,,}`, no `declare -A`. Guard empty arrays under `set -u` (see the `nullglob` comment in `lint-workflows.sh`).
- Actions are pinned to a commit SHA with a `# vX.Y.Z` comment. The checkout pin also lives in `CHECKOUT_ACTION` in `scripts/setup`; change both.
- Secret variables need `sensitive = true`, otherwise `tofu show` prints them into the pull request comment.
- The provider lock files hold one tool only. After a provider or tool change, regenerate both with `<tool> providers lock -platform=linux_amd64 -platform=darwin_arm64` in `.` and in `bootstrap/`.
- Placeholders are `REPLACE_ME`. Do not fill them in; `name_prefix` fails validation on purpose until the user replaces it.
- Language of code, comments, and docs is English. Commit messages say what changed and why.

## Verify

```bash
pre-commit run --all-files      # fmt, validate, tflint, shellcheck, shfmt, gitleaks, actionlint, zizmor, mapping tests
bash scripts/pipeline-test.sh   # after any change to scripts/pipeline.sh; add a test for the change
bash scripts/lint-workflows.sh  # after any change to .github/ or scripts/setup
scripts/setup --render          # after changing the generator; must leave the committed templates unchanged
```

`tofu validate` needs `tofu init -backend=false` first; pre-commit does that. There is no AWS access in CI or in tests; nothing here should need it.

## When changing behavior

Update README.md or docs/pipeline.md in the same change. Say in the pull request whether repositories created from this template need to do something after adopting the change.
